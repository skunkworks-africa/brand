Design system/Patterns & experiences
Patterns & experiences / 1.0

A clear route to the right workspace.

Account entry belongs in the global header, with an explicit destination and purpose.

Current destinations

Employee workspace / Microsoft 365 ↗Academy profile / Portal ↗

This design system is public. The account menu links to existing workspaces. It does not sign visitors into this documentation site or infer employee roles.

Implementation pattern

  • For an authenticated application, use Microsoft Entra ID and an approved application registration.
  • Validate tokens and authorisation in the service, not only in browser controls.
  • Show a clear signed-in identity and an explicit sign-out action only when a real session exists.
  • Use the least privilege needed and keep secrets out of static sites.
  • Let people understand where sign-in will take them. Preserve their intended destination using a validated return URL.
  • Handle expired sessions, denied access and service failures with useful recovery paths.

Integration reference

Microsoft identity platform documentation ↗. Configure tenant, application and redirect URIs in the consuming application.
